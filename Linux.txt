Virtualization ka simple matlab hai: ek physical computer ke resources ko use karke multiple virtual computers/machines banana.

Example: Tumhare paas ek laptop hai jisme Windows chal raha hai. Virtualization ki help se tum usi laptop ke andar:

🖥️ Windows
🐧 Linux
🐳 ya doosra operating system
virtual machine (VM) ke form mein chala sakte ho.


  Physical Computer
              │
       ┌──────┴──────┐
       │ Hypervisor  │
       └──────┬──────┘
          ┌───┴───┐
          ↓       ↓
       VM 1      VM 2
      Windows    Linux

Hypervisor wo software/layer hota hai jo physical hardware (CPU, RAM, storage) ko virtual machines ke beech manage karta hai.


Hypervisor ki 2 main types hoti hain:

Type 1 — Bare-Metal Hypervisor

Directly physical hardware par install hota hai.
Beech mein host operating system nahi hota.
Performance aur security generally better hoti hai.
Examples: VMware ESXi, Microsoft Hyper-V, Xen, KVM

Type 2 — Hosted Hypervisor

Pehle host operating system (Windows/Linux/macOS) install hota hai, phir uske upar hypervisor chalta hai.
Personal computers aur testing ke liye common hai.
Examples: Oracle VirtualBox, VMware Workstation, Parallels Desktop

2. User, Group, Others

Har file ke 3 permission groups hote hain:

rwx | r-x | r--
 ↑      ↑      ↑
User   Group  Others
User / Owner

File ka owner kya kar sakta hai.

Group

Jis group ko file assign hai, us group ke members kya kar sakte hain.

Others

Baaki sab users kya kar sakte hain.

3. Text wali permissions

Suppose:

rwxr-xr--

Break karo:

rwx | r-x | r--
Owner = rwx
r = read
w = write
x = execute

Owner ko read + write + execute sab allowed.

Group = r-x
r = read
- = write nahi
x = execute

Group read aur execute kar sakta hai, write nahi.

Others = r--

Sirf read allowed.

So:

rwxr-xr--

means:

Owner: read/write/execute
Group: read/execute
Others: read

1. SSH — Server ko Remotely Access Karna
SSH = Secure Shell

SSH ka use apne computer se kisi remote Linux server mein securely login karne ke liye hota hai.

Example:

ssh saqib@192.168.1.50

Iska matlab:

ssh       → SSH program
saqib     → server ka username
192.168.1.50 → server ka IP

Aapke computer par terminal hai aur server kahin internet par hai:

Your PC
   |
   | SSH
   ↓
Linux VPS

Login ke baad aap server ka terminal use kar sakte ho.

SSH Key
Password se login karne ke bajaye SSH key use karna zyada secure/common hai.

Do keys hoti hain:

Private Key → sirf aapke computer mein
Public Key  → server par

Key generate:

ssh-keygen

Usually keys yahan hoti hain:

~/.ssh/id_ed25519
~/.ssh/id_ed25519.pub

.pub = public key.

Private key kisi ko nahi deni.

authorized_keys
Server par:

~/.ssh/authorized_keys

mein authorized public keys rakhi ja sakti hain.

Concept:

Your PC
Private Key
    ↓
    SSH
    ↓
Server
Public Key
authorized_keys

Agar matching key ho to server authentication allow kar sakta hai.

SCP
SCP = Secure Copy

Computer se server par file bhejna:

scp app.zip saqib@server-ip:/home/saqib/

Server se computer par:

scp saqib@server-ip:/home/saqib/app.zip .

rsync
rsync files/folders synchronize karne ke liye useful hai.

rsync -av project/ saqib@server-ip:/var/www/project/

Large projects ya repeated transfers mein useful hai kyunki zaroorat ke mutabiq changed data transfer kar sakta hai.

2. Pipes & Redirection
Ye Linux commands ko combine karne ke liye bohat important hai.

Pipe |
Ek command ka output doosri command ko de deta hai.

ps aux | grep nginx

Flow:

ps aux
  ↓
all processes
  ↓
grep nginx
  ↓
sirf nginx wali lines

>
Output ko file mein write/overwrite karta hai.

echo "Hello" > test.txt

Agar test.txt pehle se hai to purana content overwrite ho jayega.

>>
Output ko file ke end mein append karta hai.

echo "World" >> test.txt

Purana content rahega aur World add ho jayega.

<
File ko input ke taur par use karta hai.

Concept:

command < file.txt

2>
Errors ko alag file mein bhejta hai.

command 2> error.txt

Linux mein generally:

0 = stdin
1 = stdout
2 = stderr

2>&1
Error aur normal output dono ko same destination par bhejne ka common syntax.

Example:

command > output.txt 2>&1

Matlab:

normal output → output.txt
error          → output.txt

3. Text Processing
Server par logs aur files search/analyze karne ke liye bohat useful.

grep
Text search karta hai.

grep "ERROR" app.log

Matlab app.log mein jahan ERROR hai woh lines dikhao.

Example:

grep "404" /var/log/nginx/access.log

sed
Text ko modify/replace karne ke liye.

sed 's/old/new/g' file.txt

Matlab:

old → new

awk
Structured text/data process karne ke liye.

Example:

awk '{print $1}' access.log

Ye har line ka first field print kar sakta hai.

cut
Text ka specific part nikalne ke liye.

cut -d: -f1 /etc/passwd

: separator hai aur first field nikal raha hai.

sort
Lines ko sort karta hai:

sort names.txt

uniq
Duplicate adjacent lines remove/count karne ke liye.

sort names.txt | uniq

wc
Count karta hai.

wc -l file.txt

-l = lines count.

4. File Searching
find
Files/directories search karne ke liye.

find . -name "*.js"

Current directory ke andar .js files find karega.

Example:

find /var/www -name "index.html"

locate
File ka naam quickly search karne ke liye:

locate nginx.conf

which
Batata hai command actually kahan se execute ho rahi hai.

which node

Output example:

/usr/bin/node

whereis
Program ki binary aur related locations find karne mein help karta hai.

whereis nginx

     ↓

Example:

       ↓
example.com

Simple concept:

Domain
  ↓

  ↓

  ↓
IP

   ↓

   ↓

   ↓

12. Nginx Reverse Proxy
Ye Web Developer ke liye bohat important hai.

Suppose Node.js application:

localhost:3000

par chal rahi hai.

User browser mein:

open karta hai.

Hum Nginx ko beech mein rakhte hain:

Browser
   ↓
example.com
   ↓
Nginx :80/:443
   ↓
Node.js :3000

Nginx request ko Node.js application tak forward karta hai.

Isko reverse proxy kehte hain.

Nginx configuration mein commonly:

location / {
    proxy_pass http://localhost:3000;
}

19. CORS
CORS = Cross-Origin Resource Sharing

Suppose frontend:

http://localhost:5173

Backend:

http://localhost:3000

Dono ka origin same nahi hai because ports different hain.

5173 ≠ 3000

Browser security rules ki wajah se backend ko appropriate CORS policy configure karni pad sakti hai.

Concept:

Frontend
localhost:5173
     ↓
     API Request
     ↓
Backend
localhost:3000

CORS decide karta hai browser ko ye cross-origin request allow karni hai ya nahi.

20. Basic Server Security
Root vs Normal User
Root ke paas bohat high privileges hote hain.

Isliye daily application work ke liye normal user use karna better practice hai.

Administrative kaam:

sudo command

SSH Security
Better practice:

SSH key authentication

rather than relying only on passwords.

Private key:

DO NOT SHARE

Firewall
Firewall network traffic control karta hai.

Example UFW:

sudo ufw allow 22
sudo ufw allow 80
sudo ufw allow 443

Concept:

22  → SSH
80  → HTTP
443 → HTTPS

Agar Node.js application internally 3000 par Nginx ke peeche hai, to normally 3000 ko public internet par open karna zaroori nahi.

Internet
   ↓
80/443
   ↓
Nginx
   ↓
localhost:3000

21. Secrets
Ye Web Developer ke liye bohat important security rule hai.

❌ Code mein:

const password = "mypassword123";

❌ GitHub par:

DATABASE_PASSWORD=secret

Better:

.env

Example:

DATABASE_URL=...
JWT_SECRET=...
API_KEY=...

Aur .gitignore mein:

.env

22. File Permissions in Deployment
Suppose Nginx ko website files read karni hain.

Aapko ensure karna hota hai ke appropriate user ko required access ho.

Check:

ls -l /var/www/project

Example:

-rw-r--r-- index.html

Yahan:

Owner  → rw-
Group  → r--
Others → r--

Web server ko file read karni ho to unnecessarily 777 dena bad practice hai.
